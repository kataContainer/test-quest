**Ситуация**:
Вы получаете алерт: на одном из prod-хостов закончилось дисковое пространство. Сервис деградировал. На хосте размещены Docker-
контейнеры.

1. Опишите по шагам, как вы будете диагностировать причину.
```
# 1. Проверяем сколько места осталось и что его занимает

df -h # Смотрим на разделы, заполненные на 100%. Может быть / или /var/lib/docker или /var/log

# 2. Смотрим что конкретно занимает место
du -sh /var/lib/docker/*  # Выведет по директориям что разрослось - containers/ || volumes/ || rootfs/ || buildkit/

du -sh /var/log/* # Проверка системных логов 

# 3. В докере есть внутренняя информация для df
docker system df # В столбце reclaimable находится то, что можно удалить комадной 'docker builder prune' 

``` 

2. Какие Docker-команды и системные утилиты будете использовать?
```
df -h # общая картина по дискам
du -sh # размеры конкретной директории
journalctl --disk-usage # размер systemd-журнала
lsof +L1 # проверка на удаленные файлы с открытым дескриптором
docker system df # общая картина в докере
docker ps -a --size # отображение размера каждого контейнера
ls -lhS /var/lib/docker/containers/*/ # ищем самые большие лог файлы
```

3. Как быстро освободить место без остановки сервисов, если проблема в Docker?
```
docker image prune -a --filter "until=168h" # удаляем образы старше 7 дней, которые не используются запущенными контейнерами

docker builder prune -af # очищаем билд кэш

docker system prune -f # убираем остановленные контейнеры и неиспользуемые сети, и осиротевшие образы

# Если предыдущие шаги слабо помогли или проблема в огромных логах, то можем использовать следующее
truncate -s 0 /var/lib/docker/containers/<id>/<id>-json.log # обнуляет лог-файл контейнера. 

```
